# MAX Chat · GREEN-API

Минимальный React-клиент для отправки и получения текстовых сообщений в MAX. **React 19 · TypeScript strict · Tailwind CSS 4 · Feature-Sliced Design.**

[English documentation](README.en.md) · [Требования и план](docs/REQUIREMENTS.md) · [Отчёт проверки](docs/VERIFICATION.md)

## Быстрый запуск

Нужен Node.js **22.13+** (рекомендуется актуальная Node 22 LTS) и npm. Секреты и `.env` не нужны.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (обычно `http://127.0.0.1:5173`).

Проверка production-сборки:

```sh
npm run build
npm run preview
```

Для статического хостинга публикуйте **только `dist/`** через HTTPS. Внешние шрифты, аналитика и сервер приложения не используются. `preview` — локальная проверка, а не production-сервер.

## Подключение к MAX

1. Создайте **MAX-инстанс** в [кабинете GREEN-API](https://console.green-api.com/) и авторизуйте аккаунт MAX. WhatsApp-инстанс не подходит.
2. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance` из кабинета. Введите их на экране входа; приложение проверяет `getStateInstance`.
3. В настройках инстанса оставьте `webhookUrl` пустым, включите `incomingWebhook: yes`; для статусов доставки — `outgoingWebhook: yes`. Приложение не меняет настройки инстанса автоматически.
4. Введите номер получателя РФ (`+7` и 10 цифр) или РБ (`+375` и 9 цифр). `CheckAccount` проверяет номер и возвращает настоящий MAX `chatId`. Поиск может быть запрещён настройками получателя.
5. Создайте чат и отправьте текст. Enter отправляет, Shift+Enter добавляет строку. Максимум 4000 символов. Ответьте с аккаунта получателя в MAX — ответ появится в чате.
6. «Выйти» отменяет запросы и очищает сессию. Перезагрузка тоже удаляет локальную историю и реквизиты.

Используйте отдельный тестовый инстанс и одну вкладку приложения: очередь уведомлений общая для инстанса. Другой потребитель той же очереди может забрать уведомление первым. После обработки вызывается `DeleteNotification`; неподдерживаемые события тоже подтверждаются, чтобы не блокировать очередь.

## Команды и тесты

```sh
npm run lint           # ESLint (0 warnings) + Prettier
npm run typecheck      # strict TypeScript
npm test               # Vitest + Testing Library
npm run test:coverage  # покрытие критической логики и пороги
npm run build          # проверка типов + production bundle
npm run format         # форматирование
```

Тесты охватывают API-контракты, валидацию, дедупликацию, порядок обработки/подтверждения, backoff, отмену, гонки, двойные отправки, ошибки, IME, XSS и полный пользовательский сценарий. HTTP подменяется; реальные сообщения не отправляются. GitHub Actions повторяет проверки при push/PR.

Для ручной проверки без аккаунта при работающем `npm run dev` откройте `/tests/browser/`. Введите `https://3100.api.green-api.com`, `123`, `fake-token` и номер `+79991234567`. Это **локальный тестовый стенд**, который перехватывает все запросы и возвращает искусственный ответ. Мобильный стенд: `/tests/browser/mobile.html` (iframe 390 × 844). Эти файлы не входят в production-сборку. Не вводите в стенд реальные секреты.

## Архитектура FSD

```text
src/
  app/                 # точка сборки, ErrorBoundary, Tailwind
  pages/messenger/     # жизненный цикл сессии
  widgets/messenger/   # компоновка списка чатов и переписки
  features/connect/    # подключение инстанса
  features/messaging/  # создание чата, отправка, polling
  entities/chat/       # типы, обработка событий, лента сообщений
  shared/api/          # HTTP-клиент, проверка контрактов Zod
  shared/lib/          # валидация
  shared/ui/           # кнопки, аватар, сообщения об ошибках
  test/                # настройка и интеграционные тесты
```

Слои импортируют нижележащие через публичные `index.ts`; внутренние модули слайса могут импортировать друг друга. Нет зависимостей между соседними features. Общие API/валидация не зависят от React. Небольшой внешний store с `useSyncExternalStore` управляет сессией; React отвечает за отображение и локальные поля форм. Отдельная state-библиотека и роутер для одного экрана не нужны.

## Решения и допущения

- Макет переписки MAX доступен только после авторизации. Использована привычная двухпанельная компоновка, фиолетовый акцент, отдельные входящие/исходящие сообщения; это не заявление о pixel-perfect соответствии закрытому макету.
- `apiUrl` добавлен к двум полям из ТЗ, поскольку он требуется контрактом API. Принимаются только HTTPS-адреса `api.green-api.com` и его кластеров; редиректы запрещены, чтобы не отправить токен на другой сайт.
- Проверка телефона следует ограничениям MAX CheckAccount: РФ/РБ. Приложение не подменяет MAX интеграцией WhatsApp.
- Токен, переписка и черновик — только в памяти. Нет localStorage, cookie, логирования ключей, HTML-инъекции или `dangerouslySetInnerHTML`. React экранирует текст. Frontend-приложение не может скрыть пользовательский токен от самого браузера; для многопользовательского продукта нужен backend/BFF.
- Polling последовательный, long poll 30 секунд, общий таймаут 45 секунд, пауза 250 мс; при сбоях backoff до 30 секунд. 401/403 останавливают автоматические повторы. Все запросы отменяются при выходе. Повтор уведомления не создаёт дубликат сообщения.
- Успех SendMessage означает «В очереди», не доставку. Статусы изменяются по событиям API. Сетевая ошибка отправки неоднозначна: автоматического повтора нет, текст сохраняется, пользователь проверяет MAX перед повтором.
- Пока сообщение отправляется, переключение чатов заблокировано, чтобы не потерять черновик при ошибке. Между обычными переключениями черновики не сохраняются.
- История до подключения не запрашивается; новые текстовые входящие создают диалог. Вложения, группы как отдельный сценарий, контакты, поиск и редактирование сообщений вне ТЗ.
- Зависимости установлены из npm registry и закреплены lockfile. TypeScript 6 выбран из-за peer-range typescript-eslint `<6.1`; jsdom 29 — для совместимости с установленным Node 22.21.1. Использование `--force`/`--legacy-peer-deps` не требуется.
- Для небольшого одноэкранного приложения разбиение bundle на lazy-чанки не даёт полезного выигрыша; изображения и тяжёлые дополнительные экраны отсутствуют. Tailwind генерирует только используемые стили; иконки tree-shaken.

## Ограничения проверки

Интеграционные тесты используют подменённые HTTP-ответы по контрактам GREEN-API; **живой обмен с MAX, CORS и тарифные ограничения конкретного инстанса не проверены**. В [отчёте](docs/VERIFICATION.md) есть ручной checklist.

При дополнительном времени: E2E в Chromium/WebKit, автоматический a11y-аудит, виртуализация большой истории, BFF с серверной сессией и координация нескольких вкладок. Эти изменения не включены, чтобы сохранить минимальный объём ТЗ.
